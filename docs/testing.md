# 测试与课堂评估

本文是待执行方案，不是测试结果。测试者、设备、版本、执行时间和观察结果填入 `evaluation/results-template.csv` 的副本；保留模板为空。当前未填写的数据不能用于计算成功率。

## 1. 开发检查

依赖安装完成后，在仓库根目录运行：

```powershell
python -m pytest backend/tests -q
```

在 `web` 目录运行：

```powershell
npm run test
npm run build
```

记录实际命令、退出状态和失败项。自动测试通过仅代表所覆盖的逻辑和模拟路径通过，不能代替真实服务、相机、手机或用户验证。

检查 `/api/health` 时区分“已填写配置”和“真实调用成功”。不要将 `live_available=true` 写作密钥验证通过。

## 2. 不用相机的 mock 检查

1. 不填写模型密钥，不开启相机，进入明确标识的 mock 模式。
2. 输入目标，按照页面推进 search → position → calibration → guide → verify → success。
3. 确认提示包含模拟说明，不能让人误以为系统真的看到了手或物品。
4. 分别选择目标未发现、拿错、遮挡等模拟场景，检查相应的继续扫描、拿错或不确定分支。
5. 引导中暂停、重听、重新开始；旧请求不得改变新任务，停止操作不得继续播报旧方向。
6. 记录“模拟流程符合预期／不符合预期”。mock 的 `confirmed` 不计入真实抓取成功率。

## 3. live 入场检查

- 使用固定支架、安全无尖锐边缘的桌面物品，观察员可以随时中止。先睁眼调试系统，再决定是否做短时蒙眼流程体验。
- 手机网页通过受浏览器信任的 HTTPS 访问。相机和麦克风授权在手机上重新验证，不能用电脑 localhost 成功替代。
- 用户明确同意画面上传后才运行 live。模型密钥留在后端；手机拍摄范围内不放个人证件、聊天内容等无关信息。
- 浏览器只优先请求后置镜头，不保证所有手机都会选中它；现场确认实际取景。iOS 等浏览器的权限、视频播放和语音播报需要真实设备与触控测试。
- 首次实际 API 调用成功后才能记录服务可用。无效密钥、限流、超时分别记录实际错误；不得把它们改成模拟成功。
- 相机位置改变、页面隐藏或引导暂停后重新校准。以用户本人“左、右、靠近身体、远离身体”为方向参照。
- 确认口述目标可以检查和修改；语音转写失败时明确保留错误或改用文字输入，不能伪造识别文本。
- mock 中可选语音输入仍是实际录音转写；同样检查同意与上传时机。录音期间尝试对照或开启相机，确认不会让 10 秒停止机制失效。

## 4. 12 条用例的使用方法

`evaluation/cases.csv` 是设计用例草案，所有 `review_status` 初始为 `pending_review`。任务 6先审核期望行为，补充真实输入或现场布置；它不是已采集的模型测试集。批准后的每次运行在结果表新建一行。

对涉及画面的用例，记录无个人信息的资产编号和人工标注。画面仅在取得同意后临时用于评估，不提交到版本库；不要为了复现将 API 密钥、录音或完整 data URL 放进日志。图片真实身份、手是否抬起物品、是否拿对，须由现场观察或已审核素材给出，不能从模型结果倒推。

旧帧、非法确认等路径可用测试替身验证规则；这能验证“规则是否执行”，不能验证“真实模型是否看懂了抓取”。人工预期与实际观察必须分列。

## 5. baseline 与 accessible 对照

两套提示词使用相同模型、目标、图像序列、校准信息和参数；记录提示词版本。先固定输入再调用两种风格，避免把不同光线、物品位置或采集时刻误算成提示词效果。

baseline 仅用于离线回放或观察比较，不让蒙眼参与者依据其结果执行手部移动。人工评审非视觉表达时可暂时隐藏风格名称、交替展示顺序；模型输出不自动成为正确答案。mock 文字适合检查界面，不适合证明提示词优化提升识别能力。

| 指标 | 记录口径 | 用途 |
| --- | --- | --- |
| 人工实际结果 | 正确／错误／无法判断／未执行 | 与模型确认分开，识别误确认 |
| 判断是否符合审核标准 | 通过／未通过／未执行／不适用 | 观察找错、遮挡和正确核验表现 |
| 单步可执行表达 | 0：无法执行；1：需追问；2：参照清楚且一个动作 | 比较提示词表达，不代表移动安全保证 |
| 端到端提示时延 | 从当前画面采集至有用提示开始播报；无播报留空 | 发现采集、网络和播报负担 |
| 人工帮助次数 | 观察员额外操作或解释计一次 | 发现流程独立性问题 |
| 错误与中止原因 | 简短事实描述 | 支持修复和课程反思 |

后端 `latency_ms` 仅是后端计时，不等于完整提示时延；不具备端到端计时时留空，不能用它代替。展示对照时分开统计模式、风格和场景，并给出实际样本数；只有一两次试用时报告逐条观察，不作泛化结论。

网页导出的“任务记录”是事件日志，不等同于 `evaluation/results-template.csv` 的人工评估表。审核员需补充用例编号、版本、人工真值和实际执行情况，再形成评估记录；不能直接把一行事件当作一次成功试验。

## 6. 需要明确检查的失败路径

- 没有有效参考图、校准失败或手不可见：不能输出继续移动的指令。
- live 方向响应距采集超过 6 秒：不执行旧方向提示；这可能频繁发生，需记录为体验限制，不随意放宽规则。
- 新任务已经开始、页面隐藏或用户暂停：旧 session/request 的响应不能恢复动作。
- 只有物体消失、手遮住目标或单帧重叠：不能确认拿到正确物品。
- 真正拿错：不显示成功；无法看清：返回不确定并要求重新观察。
- 权限拒绝、录音不可用、网络断开：说明原因，可取消，不静默切换 live 为 mock。
- 键盘与读屏：主要按钮有名称与焦点，状态可听，暂停、重听、取消不依赖视觉定位。
